## ⚙️ 1. General structure

The `Cafes` page is designed around a grid of cafes (`CafeCard` components) with modal pop-ups for details. It uses:

* `i18next` for translations
* Data-driven rendering from `src/data/cafes.ts`

## 🚀 2. Performance considerations

### ✅ Good points

✔ **`loading="lazy"`** is used on all `<img>` elements
✔ **`motion` whileInView** ensures off-screen animations don’t all render immediately
✔ **`useIsMobile`** avoids heavy 3D transforms on mobile
✔ **Framer Motion delays** are staggered and not CPU-intensive
✔ Cards and modals are reusing layout animations (`layoutId`) properly — great for GPU acceleration

All that is **excellent**. You’re leveraging Framer Motion *efficiently*.

---

### ⚠️ Areas to optimize or refine

#### **1️⃣ Too many motion animations in view**

Every `CafeCard` mounts with:

```tsx
initial={{ opacity: 0, y: 50 }}
whileInView={{ opacity: 1, y: 0 }}
viewport={{ once: true, margin: "-100px" }}
```

If your café grid is large (say 30–50 items), that’s a lot of independent observers.
👉 **Fix:**
Wrap the grid in one motion container, and use staggered children animations instead:

```tsx
<motion.div
  variants={{
    visible: { transition: { staggerChildren: 0.1 } },
    hidden: {},
  }}
  initial="hidden"
  whileInView="visible"
>
  {cafes.map((cafe, i) => (
    <motion.div key={cafe.id} variants={{ hidden: { opacity: 0, y: 30 }, visible: { opacity: 1, y: 0 } }}>
      <CafeCard cafe={cafe} />
    </motion.div>
  ))}
</motion.div>
```

That means **one observer and one animation context** instead of dozens.

---

#### **2️⃣ Framer Motion + heavy transforms**

The cards use `rotateX`, `rotateY`, and scaling effects — visually nice, but these **trigger GPU layers per element**.
That’s fine for a handful of cards, but if you ever have 20+ visible at once, it’ll raise GPU compositing cost.

👉 **Fix:**
On desktop only, limit 3D effects to hover or interaction rather than initial load.

---

#### **3️⃣ Modals render full overlays each time**

In `EateryDetailModal`, you’re rendering a `motion.div` with:

```tsx
className="fixed inset-0 z-50 flex items-center justify-center bg-black/60 backdrop-blur-md p-4"
```

and nested AnimatePresence trees. That’s good for smooth entry/exit, but note:

* Backdrop blur is **expensive** (forces GPU compositing)
* The large modal component mounts/destroys on every click

👉 **Fix:**
Use Framer Motion’s `presence={false}` + conditional animations to **reuse the modal node** instead of unmounting it fully each time.

Or wrap it in `<LazyMotion>` (Framer Motion feature) so only required motion features are loaded.

---

#### **4️⃣ Image sizing / layout shift**

Images inside cards use:

```tsx
<img src={cafe.logoUrl} className="w-full h-full object-contain" />
```

No intrinsic width/height attributes, which means layout shifts can occur before the image loads.

👉 **Fix:** Add aspect-ratio or width/height hints:

```tsx
<div className="aspect-[4/3] relative">
  <img src={...} alt={...} loading="lazy" className="absolute inset-0 w-full h-full object-contain" />
</div>
```

---

#### **5️⃣ Missing React.memo for heavy child components**

`CafeCard` and `EateryDetailModal` don’t memoize — not a huge issue unless the parent re-renders frequently, but for animation-heavy components, it’s smart to add:

```tsx
export const CafeCard = memo(({ cafe, index, onClick }: CafeCardProps) => { ... });
```

---

### 🧩 3. Integration with Lenis smooth scroll

You’re using `SmoothScroll.tsx` (Lenis).
Lenis changes the scroll container via transforms, which means:

* In-view triggers (`whileInView`) rely on IntersectionObserver — which *can misfire* when Lenis applies transforms.
  If you ever notice some cards not animating when scrolling slowly, that’s why.

👉 Fix:
Use Framer Motion’s `scroll` hooks (`useScroll`) tied to `window` instead of relying purely on `whileInView`, or wrap the café grid in a fixed-height scroll container managed by Lenis.

---

### 🧠 4. Minor best practices

✅ Use `useCallback` for modal open/close handlers (to avoid re-renders).
✅ Consider preloading café images with a small IntersectionObserver preload script.
✅ In production, disable Framer Motion dev tools (`<LazyMotion>` helps).
✅ If you’re targeting low-end devices, limit blur or transparency in modal backdrops.
